# sessions/ — Longitudinal Memory

## Purpose

Each session log captures: the operator's domain, the gate answers, the working avatar, the provisional thesis, and what changed the thesis (if anything). Reading recent sessions lets the researcher pick up where it left off without re-running the gate.

## Format

```
[DATE] — [DOMAIN]
Mode: scratch / sharpen
Avatar under investigation: [description]
Gate answers: [summary]
Thesis at session end: [one-sentence verdict]
What changed: [if the thesis evolved mid-session, note what changed it]
Unknowns remaining: [what to close next time]
```

## Reading order

On session start, read the most recent 1–3 logs if the operator is returning. Do not re-run the gate on questions already answered.
